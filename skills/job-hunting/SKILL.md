# Job Hunting 求职自动化

通过 ego-browser 操作用户**已登录**的求职账号：搜岗位 → 打招呼投简历 → 扫描未读 → 按规则回复。
本 skill 是规则大脑；所有对外文本由「用户画像」驱动，绝不编造画像之外的信息。

## 第 0 步：启动自检（每次任务开始前）

1. **ego-browser 可用性**：运行 `ego-browser skill`（PATH 无命令时依次尝试
   `~/.local/bin/ego-browser`、`/Applications/ego lite.app` 内的 Helper）。失败 → 打印
   安装指引（见 [references/setup.md](references/setup.md)）后**停止**，不要硬闯。
2. **画像可达性**：读取用户画像（存储策略见下）。不存在 → 走 F1 问卷；存在 → 直接使用，不重复提问。
3. **平台登录态**：打开目标平台首页确认已登录（如 Boss 显示用户名/猎聘显示"你好，X先生"）。
   未登录 → 引导用户在 Ego Lite 里登录后再继续。

## 画像存储策略（F1N）

- **首选 OpenViking**：若会话有 openviking MCP 工具（`mcp__openviking__*`），画像以 JSON
  写入并读取自 `viking://~/memories`，键名固定 `job-hunting/profile`，带 `schema_version`。
- **降级本地文件**：OpenViking 不可达时，读写 workspace 的 `job-profile.json`。功能等价，
  仅失去跨设备同步；首次降级时告知用户一次即可。
- 两种模式下画像字段完全相同（见 F1 表）。敏感信息只存于**用户自己的** OpenViking 账号或本机文件。

## F1. 前置引导问卷（画像为空时执行）

一次性把下表分组发给用户（允许跳答；**跳答项记为 `manual` 档，绝不猜测填写**）：

| 分组 | 问题 | 档位 |
|---|---|---|
| 环境 | ① 用什么平台求职：Boss直聘 / 猎聘 / 多个 | auto |
| | ② 该平台是否已登录（自检代查，不问） | — |
| 硬性条件 | ③ 学历是否统招？④ 学信网是否可查？⑤ 毕业年份/工作年限？⑥ 接受出差/驻场吗？ | auto |
| 薪资与流动 | ⑦ 目前薪资结构（base/绩效/年终）⑧ 期望薪资（区间+底线；**投递判定只看岗位上限是否 ≥ 底线**，见 F2）⑨ 离职原因（标准话术）⑩ 到岗时间 | auto |
| 沟通偏好 | ⑪ 常用打招呼语（默认"你好"）⑫ 简历回复话术（默认"你好，这是我的简历"）⑬ 默认简历文件名（平台上上传的名字）⑭ 语言风格：正式/随和 | auto |
| 红线清单 | ⑮ 哪些话题必须人工回答（GitHub/博客链接、住址、竞业细节、offer 承诺、面试爽约解释…） | manual |
| 投递筛选偏好 | ⑯ HR **活跃度**下限：今日活跃 / 3日内 / 7日内 / 一个月内（默认 7日内；筛掉长期不登录的"僵尸岗"）⑰ 公司规模：20人以下 / 20人以上 / 100人以上 / 500人以上 / 1000人以上 / 10000人以上（默认不限，可多选区间）⑱ 其他常用条件（行业、融资阶段、双休等，自由文本） | auto |
| 值守偏好 | ⑲ 值守时间窗（默认工作日 09:30/12:30/15:30/18:30）⑳ 单轮回复上限（默认 5）㉑ 缓冲话术（默认"好的收到，这个我确认后稍后回复您～"） | auto |

存画像时记录 `schema_version`；日后加字段不清洗旧数据，缺字段按 `manual` 处理。

## 铁律（优先级最高，任何模式都生效）

1. **回复 HR 一律简短**：对打招呼/邀约只回画像里的简历回复话术（⑫），不反问一堆问题。
2. **简历只在对方积极回应后才发**（F4 触发条件）：我方发出招呼/回应后**对方未回复 → 保持等待，绝不追发简历**；对方给出积极信号（索要简历、表达面试意向、追问个人情况）才执行 F4。
3. **绝不编造**用户个人信息。画像没有 = 走 F10 缓冲流程。
4. **不做承诺类发言**：答应 offer、确认面试时间、报让步数字——超出画像 auto 档的一律转人工。
5. **尊重平台限额**：Boss 日主动沟通 ≈150，弹「已达到沟通上限」立即停止全部投递并告知用户。
6. **一个 TaskSpace 贯穿整个任务**；卡住/超时在原空间恢复，恢复不了就停下报告，**不新开窗口重试**。
7. **每个关键动作验证 + 截图留证**到 workspace。
8. 值守（无人）模式：只允许外发 `auto` 档应答与短话术；其余全部进 F10 待补充清单。

## F2. 主动投递 loop（手动/goal 触发）

**⛔ 单入口硬约束（v0.3.1，事故后定稿）**：所有打招呼/发起沟通动作**只允许通过 `scripts/apply-one.js` 执行**。该脚本内置两道闸：① 无 roster 文件直接拒绝运行；② 岗位 ID 已在 `applied-jobs.json` 里则跳过不发。**禁止 agent 手写"点继续聊→输入文本→发送"的裸流程**——两次重复招呼事故的根因都是绕过闸门的手写操作。汇报表格里每个岗位必须能对上 `applied-jobs.json` 的记录行。

输入：关键词 + 城市（+可选筛选）。缺省用画像方向或追问一次。

1. 读对应站点知识包（[references/boss-zhipin.md](references/boss-zhipin.md) / [references/liepin.md](references/liepin.md)）。
2. **应用筛选条件**（三层，全部可被用户当次指令覆盖）：
   - **硬性排除——未沟通过**：打招呼只投"从未发起过沟通"的岗位。**名单数据源（猎聘已实测）**：`https://c.liepin.com/job/record/apply`「我的投递」页——每条记录含 岗位名 + 公司 + 状态 + 时间，是官方投递账本，比 IM 会话列表可靠且无重定向问题。Boss直聘仍用消息页 `/web/geek/chat` 提取。命中名单 → 跳过；同时比对 workspace `applied-jobs.json`（岗位 ID 级）。按钮状态文案只能作补充信号、**不得单独作为判据**（猎聘「继续聊」实测常驻不变，不可靠）。同公司不同岗位默认也算已沟通。名单拉取失败 → 本轮降级 dry-run。**绝不重复给同一公司/HR 发招呼**。
   - **执行顺序硬约束**：投递 loop 的第一个浏览器动作必须是运行 [scripts/build-contacted-roster.js](scripts/build-contacted-roster.js) 拿到名单 JSON；之后每个候选在点沟通按钮**之前**必须完成名单比对并在汇报里写明判定依据（`已沟通名单命中 / 按钮状态词 / 均未见→允许`）。**没有名单就没有外发**——哪怕用户催、哪怕只投一个。
   - **单轮单发 + 同轮去重（v0.3 实测教训）**：同一轮任务里，某个岗位/公司**一旦发起过沟通，本轮不得再对它发送任何消息**——自动预设话术已经说清了应聘意图，追加"自我介绍第二遍"是重复打招呼的主要形态。开新岗位前先在内部记 `本轮已发起 = {公司+岗位ID}` 集合，命中即跳过。**跨轮防重复靠名单文件**：roster 脚本把名单落盘（workspace `contacted-roster.json`，带日期），后续任何轮投递前必须先读该文件再比对，哪怕消息页拉取失败。
   - **dry-run 零外发**：用户说 dry-run/先列清单时，禁止点击任何沟通入口（点了「继续聊」即触发平台自动招呼，等于偷跑）。dry-run 只能在列表页/卡片读取信息判断，或明确标注"未进入详情页"。
   - **画像默认**：活跃度 ≥ 画像⑯（默认 7日内活跃）；公司规模满足画像⑰；其他常用条件按画像⑱。
   - **当次交互确认**：执行前列出本次生效的筛选组合（如"7日内活跃 · 100人以上 · 未沟通过"），用户当场可改（"改成今日活跃""规模不限"），改后写回画像使其持久生效。
3. 搜索 → 逐条**匹配预检**：JD 硬性要求与画像冲突（学历高于用户、明确要求英语流利等）→ 跳过并记入"未投原因"；**薪资判定用上限规则**：岗位薪资区间写 `X-Y k`，只要**上限 Y ≥ 期望底线（画像⑧底线，如 18k）**即可投——下限低于底线不算冲突（下限常是经验档的起薪，能力够得着上限就行）。仅当 **Y < 底线**（整个区间都够不着）才默认跳过，除非用户当次明确说也投。汇报里薪资冲突要写明"上限 Yk < 底线 Zk"。
4. 打开详情 → 「立即沟通」（Boss）/「继续聊」（猎聘）→ 发招呼语（⑪）。系统自动附带的默认话术属正常，不重复发。
5. **到此为止，本轮不发简历**——后续是否发简历由值守轮按 F3/F4 判定（等对方回应）。
6. 验证成功判据 + 截图。汇报表格列：岗位 / **公司** / **HR（如"陈女士"，取不到写"未知"+标注）** / 城市 / 结果 / 跳过原因。

## F3. 未读消息自动回复

扫描：消息页先点「未读」；显示"暂无未读联系人"则切「全部」，按**最后发言方是否为对方**判定待回复。

决策树（每条待回复会话）：

```
对方消息意图
├─ 纯打招呼 / 岗位邀约          → 只发短回应（画像⑫），【铁律2】本轮不发简历，等对方下一步反应
├─ 积极信号（索要简历/约面试/明确意向）
│                               → 短回应 + 发简历（F4）
├─ 问 auto 档口径问题（统招？学信网？期望薪资？离职原因？）
│                               → 引用画像原文作答，一条说完；回答后若对方要简历再走 F4
├─ 问 manual 档 / 红线 / 画像外 → 发缓冲话术（画像㉑）+ 记入桌面 job-hunting-follow-ups.md（F10），不编造
└─ 意图不明 / 谈薪谈判 / 情绪类  → 不回，列入"等你处理"清单
```

**「我方已发言、对方未回复」的会话 = 等待态**：任何轮次都不主动追发（不追问、不补简历、不重复打招呼）。幂等防重规则同时兜住这类误触发。

**积极信号判定标准**（满足任一才发简历）：
- 明示要简历："发份简历""简历发我看看""方便发下简历吗"；
- 推进流程：约面试时间、询问到岗细节、"发 offer 审批""加个微信详聊"之外的平台内推进语；
- 对我方 auto 档回答表现出兴趣并继续追问岗位匹配相关的具体问题。

模糊场景（如单回一个"好的""嗯"）**不算**积极信号，保持等待。

**幂等防重**：回复前先读该会话最后几条消息；最后一条是自己发的、或与本轮拟回复内容相同 → 跳过。（schedule 崩溃重放时靠这条避免重复发送。）

## F4. 简历发送管理

**前置条件（缺一不可）**：① 本会话中对方最近一次消息构成 F3 定义的积极信号；② 我方尚未对该会话发过简历。**仅打招呼或仅收到邀约不构成发简历条件**。

1. 点「发简历」→ 弹窗内按画像⑬匹配文件名（多候选取最新）→ 点面板内最后一个「发送」按钮。
2. 成功判据：出现「附件简历请求已发送」。未见判据 → snapshot 复核；仍不确定 → 报告，不盲重点。
3. 详细选择器见站点知识包。

## F7/F11. 定时值守

口令：
- **"开启值守"** → 校验画像与 ego-browser 后，用 `schedule_create` 建立提醒（prompt 模板见下），
  把返回的 schedule id 记入 workspace `patrol-state.json`，回执时间窗列表。
- **"暂停值守"/"关闭值守"** → 读 `patrol-state.json`，逐个 `schedule_delete`，回执清理结果。
- **"值守改成……"** → `schedule_update` 原地改时间/频率。

值守 prompt 模板（按画像⑲的时间窗建提醒）：
> 按 job-hunting skill 执行一轮值守：检查 Ego Lite 是否在运行→扫描画像指定平台的未读→按 F3 决策树回复（含积极信号判定；单轮≤画像⑳条）→输出简报。异常不要新开窗口重试。

护栏：
1. 浏览器未开 → 本轮记"跳过（浏览器未运行）"安静退出，不自作主张拉起 app（除非画像开启该偏好）。
2. 值守轮**只做被动回复**，新发起沟通上限默认 0；主动投递留给手动/goal。
3. **等待态会话零动作**：我方最后发言、对方未回的会话，任何值守轮不得追发或补简历（铁律2）。
4. 同一轮会话之间 sleep 15–60s 随机间隔，模拟真人节奏。
5. 深夜（22:00–08:00）与周末默认不建提醒。
6. schedule 绑定本会话：会话删除即失效；建议每周"重新上岗"（新会话重建 schedule）。

## F10. 待补充清单（不会回的问题 = 记桌面 markdown，不发通知）

HR 问到画像外/红线信息、或意图不明不敢回时：
1. （仅画像外但属常规口径类）对该会话发送缓冲话术（画像㉑）；意图不明/谈判/情绪类**连缓冲话术都不发**；
2. **追加到桌面文件 `~/Desktop/job-hunting-follow-ups.md`**（跨平台取用户桌面绝对路径，不要写死 `/Users/xxx`；Windows 形如 `C:\Users\<name>\Desktop\`）。每条格式固定：

   ```markdown
   ## 2026-11-03 18:30 · Boss直聘 · 陈女士（法本 · AI算法工程师）
   - 对方原话：「……」
   - 分类：红线-需人工 / 画像外-可代答 / 意图不明
   - 建议答复草稿：……
   - 状态：待处理（你回复口径后改为 ✅ 并写回画像）
   ```

3. **必填字段硬校验**：每条记录的「对方」必须同时含 **HR 称呼（姓+女士/先生/职务，如"陈女士"）** 与 **公司名**——从会话列表项、聊天窗口标题区、岗位详情页三处交叉取；实在取不到写 `未知HR · 未知公司（岗位：<JD标题>）`并加一行 `- ⚠️ 身份不明，建议人工核对`。**禁止留空、禁止写"某HR""一家公司"这类含糊指代**。值守简报逐条点名时同样遵守。
4. 值守简报最后一行提示："📋 N 条待补充 → 桌面 job-hunting-follow-ups.md"；
5. 你在会话里给出口径后 → agent 写回画像对应字段 + 把该条标记 ✅（同类问题下次 auto 档直接答）。
6. 文件不存在则创建；写入失败（无桌面权限等）→ 降级写 workspace 同名文件并在简报里说明。
